Scope: `git diff bf65f14~1..HEAD` on branch
`milestone/0006-unified-command-model-and-tui`. Task-level (not per-subtask)
verdict over the two authorized product changes (SSRF canonicalization,
`tui --path-root/--no-file-paths`) and the test/tool/CI surface. Read-only

## Assets & trust boundaries

- **Untrusted input** reaching the SSRF oracle `normalizeTargetUrl` /
  `isPrivateHost` (`src/core/utils.cpp`): a `target_url` on `link.create` and on
  every `link.import` row, validated **syntactically** (no DNS, no fetch) before
  storage; the stored value is later emitted verbatim in a redirect `Location`
  header and followed by a victim's browser. This is the one trust boundary the
  product change widens/narrows.
- **Local operator filesystem** via the new `tui` path flags -> `PairFileOptions`
  -> `pair_file_access` rooted `openat` walk.
- **Test/CI supply chain**: the conformance harness spawns the real binary and
  REST servers; the child environment, argv, listener binding and uploaded
  artifacts are the boundary.

## Findings

### [MEDIUM] Backslash in the host defeats the private-target block (browser-navigable)

- **Vector / evidence:** `src/core/utils.cpp:604` splits the authority only on
  `/ ? #` (`rest.find_first_of("/?#")`), and the `%` guard at `:654` plus the
  numeric canonicalizers do not reject a backslash. WHATWG host parsing for the
  `http`/`https` special schemes ends the authority on `/`, `\`, `?` **or** `#`,
  so a browser cuts the host at the first `\` while this validator keeps it.
  A numeric-encoded loopback followed by `\` therefore fails
  `parse_ipv4_numeric` (the `\` makes the last part non-numeric,
  `src/core/utils.cpp:252-294`) and then falls through the string-prefix
  fallback (`:521-544`), which only matches dotted textual prefixes
  (`127.`, `10.`, ...) and never a bare decimal/hex/octal. Result: `isPrivateHost`
  returns `false` and the target is accepted.
  Still-open, browser-navigable vectors with private targets denied:
  - `http://2130706433\x`  (decimal -> `127.0.0.1`)
  - `http://0x7f000001\x`  (hex -> `127.0.0.1`)
  - `http://0177.0.0.1\x`  (octal -> `127.0.0.1`)
  - `http://127.1\x`       (short form -> `127.0.0.1`)
  Chrome/Firefox/Edge normalize `\`->`/`, parse the host as IPv4 and navigate to
  loopback. The bracketed IPv6 path is **not** affected (junk after `]` is
  rejected at `:628-630`), and a dotted-textual private host with a trailing `\`
  is still caught by the prefix fallback - only the numeric encodings evade.
- **Impact:** CWE-918 / CWE-601 private-target filter bypass - the same class the
  07.0/20 ruling set out to close (minting redirects to loopback/internal). This
  is a redirect service with no server-side fetch, so the blast radius is a
  victim browser being redirected to an internal/loopback origin, not direct
  server SSRF; hence MEDIUM, not HIGH/CRITICAL. `master` is affected identically
  (same code path).
- **Mitigation:** treat `\` as an authority terminator before host extraction
  (mirror WHATWG: `find_first_of("/\\?#")`), or - simpler and consistent with
  the existing `%` rule - reject any host containing a character outside the
  legal host charset (`\`, raw whitespace, other forbidden host code points)
  before classification. Add `http://2130706433\\x` and the octal/hex/short
  variants to `tests/unit/commands/ssrf_vectors.hpp` so `link.create` and
  `link.import` prove parity on the fix. Hand to `cpp-expert` (fix) and
  `testing-expert` (vectors).

### [LOW] Non-canonical host forms fall through to the prefix fallback (defense-in-depth)

- **Vector / evidence:** `isPrivateHost` strips only **one** trailing dot
  (`src/core/utils.cpp:476`) and never trims interior/leading whitespace (host
  is only lower-cased at `:642-645`; the whole-URL `trim` at `:586` does not
  reach an interior space). `http:// 2130706433/` (leading space) and
  `http://2130706433../` (double trailing dot) both fail `parse_ipv4_numeric`
  and miss the prefix fallback, so `isPrivateHost` returns `false`.
- **Impact:** unlike the backslash case these are **not** browser-navigable - a
  raw space is a WHATWG "forbidden host code point" and a double dot is an empty
  label, so the URL fails to parse in the client and no redirect occurs. So this
  is defense-in-depth drift, not an exploitable bypass. Same root cause as the
  MEDIUM: forms the canonicalizer cannot parse silently fall to a fallback that
  only knows dotted-textual prefixes.
- **Mitigation:** folded into the MEDIUM fix - a host-charset allowlist that
  rejects whitespace and reduces the numeric path to a single canonical form
  removes all three forms (backslash, whitespace, multi-dot) at once.

### [LOW] GitHub Actions pinned to mutable major-version tags

- **Vector / evidence:** `.github/workflows/ubuntu-integration-tests.yml`,
  `.github/workflows/perf-analytics.yml`, `.github/workflows/ubuntu-unit-tests.yml`
  use `actions/checkout@v4` and `actions/upload-artifact@v4` (floating tags),
  not commit-SHA pins.
- **Impact:** a compromised or force-moved tag on a third-party action could run
  arbitrary code in CI. First-party GitHub actions and least-privilege
  (`contents: read`) limit this; it matches the pre-existing repo convention, so
  it is a hardening opportunity, not a regression.
- **Mitigation:** pin to full commit SHAs with a comment naming the version
  (repo-wide follow-up, not a 07.0 blocker).

### Non-issues confirmed (no action)

- `effective_host.rfind("fc"/"fd", 0)` (`src/core/utils.cpp:542-543`) over-blocks
  any hostname starting `fc`/`fd` (e.g. `fc-barcelona.com`). Conservative
  (fail-closed), not a bypass.
- Userinfo `@` rejected for the whole authority, including multi-`@`
  (`:610-612`); `file:`/`javascript:`/`data:`/`ftp:` rejected by the http(s)
  scheme gate (`:600`); CRLF/control/U+2028-9/NEL rejected up front
  (`containsUnsafeUrlControlBytes`, `:547-574`) - a tab inside a numeric host is
  rejected here, closing the tab-strip analogue of the backslash vector.

## 1. SSRF fix as a whole

Both fix rounds (`752dad8`, `5d970c8`) are otherwise comprehensive. Verified
**closed** with private targets denied:

| Form | Status |
|---|---|
| Decimal / hex / octal / short / mixed IPv4 (`2130706433`, `0x7f000001`, `0177.0.0.1`, `127.1`) | closed (`parse_ipv4_numeric` + `is_private_ipv4`) |
| Single trailing dot on numeric/`localhost` | closed (`:476`) |
| `%`-encoded dot in host | closed (host `%` refused outright, `:654`) |
| Bracketed IPv6, split before the port | closed (`:620-632`) |
| IPv4-mapped / -compatible / NAT64 / 6to4 embedding a private v4 | closed (`classify_ipv6`), public-embedded (`8.8.8.8`) correctly still accepted |
| `::`, `::1`, `fc00::/7`, `fe80::/10`, zone-id `%` | closed (`%` -> refused; `::`/`::1`/ULA/link-local classified) |
| `localhost` / `localhost.` / `localhost.localdomain` / uppercase | closed |
| CGNAT / benchmark / multicast / reserved / broadcast | closed |
| Userinfo `@` (incl. `a@b@c`) | closed (`:610`) |
| **Backslash authority terminator + numeric loopback** | **OPEN - MEDIUM (above)** |
| Leading/interior whitespace, double trailing dot | OPEN - LOW, not navigable (above) |

**Policy judgement - refusing `%` in the host unconditionally:** endorsed. It is
scoped to the host only (path/query percent-encoding in `suffix` is preserved,
`:604-608`), it closes the encoded-dot / encoded-IP re-entry the private check
exists to block, and legitimate hosts never need percent-encoding (the one case,
an IPv6 zone-id, is not a valid redirect target). Low friction, fail-closed,
correct. The same "reject-what-you-cannot-canonicalize" instinct should be
extended to `\` and whitespace (the MEDIUM/LOW above).

## 2. tui path flags

Confinement path traced end-to-end and confirmed:
`parseTuiCommand` (`src/cli_parser.cpp:995-1005`) -> `--path-root` routed through
the **shared** `normalize_path_root` (same normalizer as `parse_serve_stdio`, so
`/foo/` == `/foo`, and `.`/`..`/`~`/non-absolute are rejected) ->
mutual-exclusion with `--no-file-paths` enforced (`:1035-1040`) ->
`tui_file_path_policy` (`src/tui/tui_entry.cpp:125-142`) ->
`runtime_options.file_paths` -> `build_command_runtime` ->
`pair_file_access` rooted `openat` walk.

- **Read-only sessions can never use paths:** confirmed. `--read-only` sets
  `caller.control_set = ControlSet::User` (`tui_entry.cpp:218`); both path forms
  raise the required permission to `write` (`link.export` path raise,
  import writes), so the registry denies `path` for a User regardless of the
  flags. Independent of the flag wiring.
- **`--no-file-paths` disables both directions:** confirmed. It sets
  `allow_paths = false` (`tui_entry.cpp:128-132`), so `path` returns
  `unsupported` for import **and** export even for a write-capable operator.
- **Default unchanged:** confirmed. Neither flag -> `allow_paths = true`,
  `root = nullopt` (`tui_entry.cpp:138-139`), i.e. today's local-operator
  full-filesystem behavior. No default regression.

## 3. Test and harness supply chain

- **Corpus steering role/read-only/paths/backend in any shim:** no. Role is
  obtained only through real production gates - REST runs **one server per
  role** (`--command-api-role admin` vs `user`, `conformance_rest.py:11-18,141`)
  and never passes role in the body; local shims get `user` only via
  `--read-only` (`30_authz_process_level.py:82-104`). The closed envelope rejects
  a `role`/`caller`/`read_only`/`principal`/`control_set` key with
  `invalid_field` (asserted by `test_read_only_flag_cannot_be_overridden_by_args`).
  Backend is fixed in-memory; no shim constructs the REST runtime with
  `allow_paths=true` (`conformance_rest.py:19`), and `lint_negative/rule_14`
  blocks an unconfined-path corpus case.
- **Hermetic child env:** yes. `conformance_env` (`conformance_common.py:539-563`)
  strips `URL_SHORTENER_STORAGE_CONFIG` and every `SHORTENER_` / `URL_SHORTENER_`
  prefixed var (base domain, slug length, `SHORTENER_ALLOW_PRIVATE_TARGETS`,
  analytics salt), so an ambient developer/CI value cannot flip a verdict.
- **List-argv spawn with timeouts and reaping:** yes. `spawn`
  (`:615-650`) rejects a string/non-str argv and never uses `shell=True`;
  `terminate_and_reap` (`:653-677`) terminates -> waits -> kills -> waits,
  idempotent; every HTTP call is `timeout`-bounded (`wait_http_ready`,
  per-request timeouts).
- **Loopback-only clients stay loopback:** yes. `free_port`/`wait_http_ready`
  bind and poll `127.0.0.1` only (`:575-607`); the REST servers are reached over
  loopback, which is also what grants the Admin role in production
  (`is_loopback_peer`).
- **Harness output / artifacts leaking secrets:** no. The summary writer
  (`conformance_common.py:1175-1196`) emits only `{transport, name, status,
  reason}` where `reason` is matcher-diff text over **public** corpus data;
  fixtures build fake secrets from `fake_secret_marker` and the env strips real
  salts, so neither the uploaded `conformance_summary_*.json` nor
  `coverage_matrix.md` can carry a real secret.

## Round 3 re-check (2026-11-21) - backslash/whitespace host bypass fix

Re-reviewed `git diff 3236711~2..3236711 -- src/core/utils.cpp
tests/unit/commands/ssrf_vectors.hpp tests/unit/core/02_url_validation_reject_test.cpp`
(fix `0bfb543`, tests `3236711`).

**Is the bypass class closed? Yes.** Two complementary controls now run before
the private-target check:
- An explicit backslash refusal over the whole authority
  (`src/core/utils.cpp:665`, before host extraction). WHATWG ends the host at
  `\` and a browser maps `\`->`/`, so `http://2130706433\x` is now rejected
  instead of being mis-parsed and stored. A `\` inside the path (`suffix`) is
  left intact, so `http://example.com/a\b` is still accepted - correct.
- A strict host allowlist `is_valid_url_host` (`:477-503`), applied in **both**
  modes (`:717`): a bracketed IPv6 literal (`inet_pton` AF_INET6), or an ASCII
  `[A-Za-z0-9.-]` registered name / numeric IPv4 with at most one trailing dot.
  The allowlisted charset is a strict subset of characters that are
  unambiguous in host position - none of them is a WHATWG host terminator or
  forbidden host code point - so the browser and this parser can no longer
  disagree on the host boundary. That is the property that closes the whole
  class, not just the three named inputs. Whitespace (`http:// 2130706433/`)
  and the double trailing dot (`http://2130706433../`) are refused by the
  charset / trailing-dot rules; numeric encodings (`2130706433`, `0x7f000001`,
  `0177.0.0.1`, `127.1`) still pass the charset and reach `isPrivateHost`'s
  canonicalizer, so loopback detection is preserved. Tab/CR/LF anywhere in the
  URL remain rejected up front (`containsUnsafeUrlControlBytes`), closing the
  tab-strip analogue. I reproduced the full matrix by inspection and it matches
  the coordinator's real-binary run (refused set and accepted set both agree,
  including `example.com/a\b`, `example.com.`, punycode, `134744072`,
  `8.8.8.8`, `[2001:...8888]:8080`, and query `%20`).

**Is anything still open? No security-relevant gap.** The MEDIUM and both LOW
host-canonicalization findings from the main report are closed. The parity
header and reject test now carry the backslash/whitespace/double-dot vectors
plus positive controls (trailing-dot FQDN, punycode, host:port), so T-40 no
longer has the vector gap called out earlier. (Residual trivia, not findings: a
bare `http://./` or `http://-/` passes the allowlist but resolves to nothing
internal - not a private-target bypass.)

**Does the allowlist over-block any legitimate host? Two benign, fail-closed
narrowings - neither a security issue:**
- **Underscore hosts** (`http://foo_bar.example.com/`): `_` is not in the
  allowlist (`:491-492`) yet is a legal, browser-resolvable host character
  (not a WHATWG forbidden code point). Such targets now return `invalid_url`.
  Rare and RFC-non-compliant, so acceptable; if underscore target hosts must be
  supported, add `_` to the allowlist. LOW, functional only.
- **Raw non-ASCII / IDN hosts** (`http://bucher.example/` written with real
  UTF-8): rejected; the host must arrive already punycoded (`xn--...`), as the
  function's own contract states. This is an intentional hardening choice
  (raw-UTF-8 hosts can carry homograph/bidi confusables) and is documented in
  the Doxygen comment; `xn--` hosts are accepted and tested. Acceptable policy
  narrowing, not a defect.

Both over-blocks are fail-closed (reject), so they cannot create a new bypass.

**Updated verdict: PASS.** The one MEDIUM is resolved with matching regression
coverage; no CRITICAL or HIGH outstanding. The two LOW over-block notes and the
earlier LOW CI action-pinning note are non-blocking follow-ups. The `master`
backport of the SSRF fix (now including this host allowlist) remains the
recommended action at the 07.0 close.
