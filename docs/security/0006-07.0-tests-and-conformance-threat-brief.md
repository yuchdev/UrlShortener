# Standing threat brief - Milestone 0006 Task 07.0 (Tests and conformance) - 2026-11-19

**Status:** STANDING THREAT INPUT. Every coder briefing for a Task 07.0 security
subtask (18, 19, 20, 21) and the review gates (31, 33, 34) cites this document.
Task 07.0 adds **no product surface**; it proves, as executable checks, the
controls that Tasks 01.0-06.0 already built. The per-threat dispositions live in
the six as-built threat models `docs/security/0006-0{1..6}.0-*-threat-model.md`;
this brief only re-points each test at the **real choke point** (file:line) so
the tests target production code, not mocks.

## How to read this

- A test whose assertion passes against a mock but would pass equally if the
  production control were deleted is **worthless**. Each subtask below names the
  choke-point function and line the test must exercise through a real in-memory
  port (pattern: `tests/unit/security/`, `tests/unit/app/app_test_fakes.hpp`,
  `commands_test::RegistryFixture` from subtask 18).
- "T-xx" are the threat IDs from the 01.0-06.0 threat models. A subtask proves a
  threat's **mitigation holds**, or (where marked) that an **invariant** is not
  regressed.
- Line numbers are as-built on branch `milestone/0006-unified-command-model-and-tui`
  at the time of writing; they drift. Treat them as "this function in this file",
  re-grep before asserting.

**Proves:** plan C6 - `db.*` exposes only `links`/`click_events`/`jobs`; no
response or audit line carries secrets, hashes, raw client identifiers, DSNs or
argument values.

**Threat IDs:** T-51 (db.* name/sort reaching SQL or escaping the allowlist),
T-52 (click_events raw client identifier / unescaped free text), T-53 /
T-85 (system.info leaking DSN/path/salt/TLS material / hardening limits),
T-94 (jobs table metadata-only), T-13 (job record exposing raw args),
T-14 / T-15 (missing/duplicated audit, log injection via audit fields),
T-10 / T-62 (exception text leaking paths/SQL/DSN), T-20 / T-74 (schema
disclosure - adjacent, owned by corpus 14).

**Choke points the tests must hit:**

|---|---|
| `db.tables` / `db.rows` resolve `table` only through the allowlist | `src/commands/db_commands.cpp:137` (`handle_db_tables`), `:202` (`handle_db_rows` via `app::TableCatalog::find`) |

**Control caveat the tests must encode (do not silently rely on CLAUDE.md):**
`redactSecretValue` (`storage_observability.cpp:38-40,43`) redacts keys
containing `password`, `secret`, `token`, and the password part of a `dsn`
value - it does **not** match a key containing `key` (CLAUDE.md overstates
this; correction is scheduled in Task 08.0/06). Therefore the primary control
for `system.info` is the **positive allowlist** (`system_commands.cpp` /
`ShortenerSettings`), not redaction. Case `system_info_emits_only_allowlisted_names`
(keys `api_key`, `x_password`, `my_dsn`, `shared_secret`) must assert those keys
never appear **because they are never emitted**, i.e. redaction is not even
reached. Do not weaken the case into "redaction scrubbed it".

**Non-negotiables for the fixture:** build fake secrets at runtime from
`fake_secret_marker` (the `secret-scan` hook blocks credential-looking
literals); assert absence by scanning the whole serialized response, not named
fields; capture audit lines through an injected `IAuditSink`, never by parsing a
log file.

## Subtask 19 - Authorization matrix (`commands__74..75`, `conformance_30`)

**Proves:** plan C7 - authorization lives in the registry, enforced before any
side effect, identically on every transport; adapters cannot bypass or override
it.

**Threat IDs:** T-08 (authz-after-validation ordering / schema leak), T-09
(`permission_for` must only **raise**, never lower), T-11 (registry authorizes
solely on `CallerContext.control_set`), T-61 (`manage_users` refused over REST
for every role/peer), T-64 / T-70 (config gate is the whole perimeter; peer
derivation fails closed to User), T-65 (same-host reverse-proxy makes every peer
loopback - operator-doc mitigation, assert the loopback check itself), T-71
(`status=all|deleted` requires write/admin), T-81 / T-115 (local operator =
Admin; `--read-only` downgrades), T-116 (mutating paths cannot bypass the
capability choke point).

**Choke points the tests must hit:**

| Control | Location |
|---|---|
| The one `max(base, permission_for(args))` rule | `src/commands/command_registry.cpp:98` (`effective_permission`) |
| Enforced inside `execute` before dispatch | `src/commands/command_registry.cpp:641-644` |
| Registration guard: mutating needs write-or-higher unless a `permission_for` can raise | `src/commands/command_registry.cpp:497-499` |
| Public read path used by the client preflight | `src/commands/command_registry.cpp:769` (`resolve_permission`) |
| `link.list` raise (`status=all|deleted` -> write) | `src/commands/link_list_command.cpp:299` (`link_status_permission`) |
| `link.export` raise (`path` -> write) | `src/commands/pair_commands.cpp:1063` |
| REST role gate, fail-closed to User, loopback-only Admin | `src/http/command_bridge.cpp:320` (`command_api_control_set`), `:328` (`is_loopback_peer`), `:357-372` (`command_api_caller`) |
| REST `manage_users` refusal regardless of role/peer | `src/http/command_bridge.cpp:141` (`rest_policy_refusal`) |

**The 2026-11-19 ruling (b) - argument-dependent permission preflight - that
this matrix MUST now cover (spec 19 as written, dated 2026-10-22, predates it):**
the matrix must assert the **registry's own** `resolve_permission` /
`effective_permission` return the **raised** permission, for the real
argument-dependent descriptors, as the single source of truth:

1. `resolve_permission(link.list, status=active)` == `read`;
   `status=all` and `status=deleted` each == `write`. (Guards T-71 at the
   descriptor, not only at the execute boundary.)
2. `resolve_permission(link.export, {path:...})` == `write`; inline export
   (no `path`) == `read`. (Guards T-9/T-118 export-to-path.)
3. The client mirror forwards to the registry and never re-implements rules:
   `InProcessClient::required_permission` (`src/tui/in_process_client.cpp:184`)
   returns `permission_name(resolve_permission(request))`; declared on
   `ICommandClient` (`include/url_shortener/tui/command_client.hpp:267`),
   relayed by `AsyncCaller::required_permission`
   (`include/url_shortener/tui/async_caller.hpp:225`) and consumed by
   `CapabilityModel::can_run(info, args)` (`include/url_shortener/tui/capability.hpp`).
   A test must prove the preflight and the executed permission agree (same
   `effective_permission`) for the two raising commands - this is exactly the
   gap that produced the 2026-11-19 HIGH x2 finding (arg-blind read-only mirror)
   fixed in `c770499`/`ec1cfe7`. TUI UX behavior (disabled `all`/`deleted`
   choices, `n/a (read-only)` counts) is proven by subtask 28; this subtask owns
   the **registry-level and client-forward equivalence**.

**What spec 19 already covers and must keep:** exhaustive descriptor iteration
(`every_descriptor_has_explicit_permission`, `mutating_implies_write_or_higher`),
`manage_users_reserved` (no such descriptor until 0002), `rest_policy_refuses_manage_users`,
authz-before-side-effects and authz-before-argspec ordering (T-08), `dry_run`
still requires permission (T-21/T-57), `read_only_export_to_path_denied`,
`test_read_only_flag_cannot_be_overridden_by_args` (closed envelope rejects a
`caller`/`role`/`read_only`/`principal` key with `invalid_field` - the
envelope-is-closed control from 01.0), and the process-level REST gate matrix
(`test_rest_gate_default_off`, `test_rest_user_role_denied_write`,
`test_rest_admin_role_loopback_only`, `test_rest_resource_routes_unchanged`).

## Subtask 20 - Import SSRF, size and path limits (`commands__76..78`, `conformance_31`)

**Proves:** bulk import/export rows traverse the **same** SSRF/URL/slug
validation as `link.create` (no second path), payloads are size-bounded, `path`
cannot escape its root or hit special files, and REST can neither read nor write
local files.

**Threat IDs:** T-40 (SSRF/URL validation stays upstream of the store -
INVARIANT), T-95 (arbitrary server-file read/write via `path`), T-96
(`--path-root` jail escape via TOCTOU / in-root symlink), T-97 (import parse /
size exhaustion), T-98 (CSV formula injection - safe by construction), T-99
(export clobbers an existing file), T-101 (bulk import must still honour the
create throttle), T-109 (inline export result size cap), T-118 (TUI `path` =
arbitrary operator read/write).

**Choke points the tests must hit:**

| Control | Location |
|---|---|
| SSRF/private-target vocabulary (shared oracle with `link.create`) | `include/url_shortener/core/utils.hpp` (`isPrivateHost`, `shortener_allow_private_targets`) |
| Path capability + root jail (the real gate, independent of transport name) | `src/commands/pair_file_access.cpp`: special-file/UNC/device/NUL reject `:40-96`; `is_within_root` `:116`; `components_under_root` `:159`; `open_rooted_parent` (O_NOFOLLOW symlink-free walk) `:200`; `PathPolicy` `include/url_shortener/commands/pair_file_access.hpp:119-131` (default `allow_paths=false`, `:125`) |
| Create-new export (never overwrites) | `AtomicExportSink::from_path` (`pair_file_access.cpp`), `O_EXCL`/`linkat EEXIST` single-committer (threat model T-99) |
| REST runtime leaves paths default-deny | `src/composition/command_runtime.cpp:233-234` (plumbs options only; REST never sets `allow_paths=true` -> `path` returns `unsupported`) |

### Ruling (a): subtask 20 must add `--path-root` / `--no-file-paths` to `tui`

This is the standing requirement, with its threat-level obligations. As built,
`serve-stdio` has both flags but `tui` has neither, and `run_tui` hardcodes the
full-filesystem capability:

- `parse_serve_stdio` **has** `--no-file-paths` / `--path-root`:
  `src/cli_parser.cpp:842-900`, normalization at `:765-817`
  (`normalize_path_root`), mutual-exclusion at `:894-896`.
- `parseTuiCommand` **lacks** both flags: `src/cli_parser.cpp:956-1002`;
  `buildTuiHelpText` (`:910-932`) does not document them;
  `TuiCliOptions` has no `no_file_paths`/`path_root` field.
- `run_tui` unconditionally sets `runtime_options.file_paths.allow_paths = true`
  with **no** confinement root: `src/tui/tui_entry.cpp:180-181`; the T-118
  limitation is spelled out in the comment at `:173-179`.

Threat-level requirements the new flags and their tests must satisfy (parity
with `serve-stdio`):

1. **Trailing-slash root normalization (prior LOW finding).** `--path-root
   /foo/` must normalize identically to `/foo` so the component-wise prefix
   check (`is_within_root`/`components_under_root`) is not defeated by a
   string-prefix trap (`/foo` vs `/foobar`). The normalizer at
   `cli_parser.cpp:765-817` already collapses separator runs and rejects `.` /
   `..` / `~` / non-absolute; the `tui` path must route through the **same**
   `normalize_path_root`, not a second copy. A regression test must assert
   `--path-root /foo/` and `--path-root /foo` yield the same confinement and
   that `/foobar/x` is refused `invalid_field`.
2. **Read-only + paths behavior.** Both path forms require `write`
   (`link.export` path raise at `pair_commands.cpp:1063`; import writes need
   write). Therefore a `--read-only` tui session cannot use `path` at all
   (server denies with `not_authorized`), and `--no-file-paths` makes `path`
   return `unsupported` even for a write-capable operator; `--path-root <DIR>`
   confines a write-capable operator to the canonical root (escape ->
   `invalid_field`, file not opened). Mutual exclusion of the two flags must be
   enforced as in `parse_serve_stdio:894-896`.
3. The wiring target is `runtime_options.file_paths`
   (`tui_entry.cpp:180-181`): `--no-file-paths` -> `allow_paths=false`;
   `--path-root D` -> `allow_paths=true, root=D`; neither flag -> today's
   `allow_paths=true, root=unset` (local-operator default preserved).

**Boundary / stale-spec note (see flags below):** this is a **product** change
in `src/cli_parser.cpp` and `src/tui/tui_entry.cpp`, which collides with Task
07.0's own key constraint "No test may touch `src/` behavior". It is here only
by explicit user ruling (2026-11-19, item 1). Route the implementation to
`cpp-expert` and the regression tests to `testing-expert`; it is not a
test-only subtask any more. Spec 20's "Files affected" table does not list
either source file or any `tui` path test - treat the ruling as the authority.

### Non-negotiables

- One shared SSRF vector list (`tests/unit/commands/ssrf_vectors.hpp`) used by
  both import-row and `link.create` tests; the per-input codes must be
  **byte-identical** (proves "no second validation path", T-40).
- Validation is **syntactic**: zero DNS lookups, zero URL fetches
  (`import_private_row_does_not_resolve_dns`).
- Filesystem cases write only under a per-test temp dir; a sentinel file
  **outside** the root must be provably unopened/unmodified after a rejected
  path (the real proof of confinement, not the error code alone).
- REST process cases must prove `path` on both pair commands returns
  `unsupported` **and** the sentinel file content never appears in any response.

**Proves:** plan C5 - `cmd`, `serve-stdio` and `tui` never construct

### Rulings (c): conformance shims (04, 06-10) must not weaken production controls

A standing acceptance condition for every shim subtask and for the 34 review
gate. The shims replay the corpus; they must obtain each role **exactly as a
real caller would**, never by relaxing a production gate:

- **REST admin is loopback-gated, per server.** `command_api_caller` grants
  Admin only when `command_api_role == "admin"` **and** the peer is loopback,
  failing closed to User otherwise (`command_bridge.cpp:357-372`). The REST
  shim (spec 08/09) must run **one server per role** (`--command-api-role admin`
  and a separate `--command-api-role user`) and route each corpus step to the
  server matching its role. It must **not** run a single blanket
  `command_api_role=admin` server and send `user`-role cases to it - that would
  silently test Admin behavior for a User case and mask T-64/T-71.
- **REST resource routes stay Admin by design (C3), gated endpoints do not.**
  `execute_resource_command` runs as Admin (`command_bridge.cpp:29`); the
  generic `POST /api/v1/commands`, `GET /api/v1/links`, `/api/v1/jobs*` use the
  loopback+role gate. The shim must not conflate the two (spec 09 already keeps
  resource routes Admin "regardless of flags" - that is correct and must stay).
- **REST file paths must remain default-deny.** No shim may construct the REST
  command runtime with `file_paths.allow_paths=true` or a `root`
  (`command_runtime.cpp:233-234`); `path` on REST import/export must stay
  `unsupported` (subtask 20 process cases assert this). Only `run_tui` and
  `serve-stdio` (under its flags) may enable paths.
- **Local shims get `user` only via `--read-only` / `CallerContext{User}`.** The
  cli (`--read-only` flag position), stdio (`serve-stdio --read-only`) and tui
  (`InProcessClient` over a `ControlSet::User` caller) shims must not pass role
  through corpus `args`/`options` - the closed envelope rejects a `role`/
  `caller`/`read_only` key with `invalid_field` (asserted by 19's
  `test_read_only_flag_cannot_be_overridden_by_args`). A shim that injects role
  via the request body would be both wrong and a C7 violation.
