# Threat Model - Milestone 0006 Task 05.0 Jobs, pairs and stdio - 2026-11-17

Design-time (pre-implementation) STRIDE-lite review and **standing input for every
implementation brief** in Task 05.0 (21 subtasks under
`docs/roadmap/0006-unified-command-model-and-tui/05.0-jobs-pairs-and-stdio/`),
plan.md "Shared contracts" C1-C11 (esp. C2/C5/C6/C7/C10), and the carry-forward
from the 01.0 review (**T-21**): every `supports_dry_run` job factory must return
a dry-run body that performs **no mutation**, bounded work, runs **synchronously
on the request thread**, with a `NoopJobContext` that cannot cancel - asserted per
command. No 05.0 product code exists yet. T-IDs start at **T-86** (01.0 = T-01..T-22,
02.0 = T-30..T-41, 03.0 = T-50..T-59, 04.0 = T-60..T-85). Findings cross-reference
rather than restate the earlier models.

## Assets & trust boundaries

- **Job runtime (in-memory):** one process-wide `JobRunner` (`std::shared_ptr`),
  `JobStore` records, cancel flags, worker threads. Shared by every
  `CommandRuntime` in the process, including REST's per-request runtimes (04.0/02).
  A job **outlives** the request that submitted it - the primary lifetime boundary.
- **Untrusted file surface (`path`/`data` args):** `link.import`/`link.export`
  name a server-side filesystem path or pass inline bytes. Path is untrusted input
  that selects a server resource; the key boundary is *which transport may name a
  path at all*. REST must never read/write an arbitrary server path (07, 08/10).
- **Pair content:** CSV/NDJSON lines from a local file or inline `data`; every row
  must traverse `LinkCommandService::CreateLink` (single SSRF/slug/validation path,
  C1).
- **NDJSON stdio wire (`serve-stdio`):** stdin = untrusted request stream from the
  parent process (script, MCP host, webview sidecar); stdout = response envelopes
  **only** (C2); stderr = logs + audit (D14). Parent owns the pipe and the audit.
- **Caller identity:** `CallerContext` synthesized by the adapter, trusted by
  `execute` as the sole authz root (01.0 T-11). `serve-stdio`/`cmd`/`tui` =
  local-operator `Admin` (`User` under `--read-only`); REST job/command routes gated
  (04.0 D4: off by default, `admin` only loopback). Jobs carry **no owner** in V1.
- **Secrets at risk:** server filesystem contents (via `path`), the full link table
  (via inline export result), job failure `what()` text (may contain paths/args),
  config values in startup logs.

## Findings

### Job queue / worker pool / shutdown (subtasks 01-03)

#### [MEDIUM] T-86 Job queue / pool / retention resource exhaustion
- Vector: `submit` on an unbounded queue, unbounded worker count, or unbounded
  retained records (`job_store.hpp`, `job_runner.hpp`).
- Impact: memory/thread DoS; silent drop of accepted work.
- Mitigation (testable): `JobRunnerOptions{worker_count=2, queue_capacity=16,
  max_retained_jobs=256}`, all validated (`std::invalid_argument` on 0); a full
  queue returns `busy` and creates **no** record (02 test asserts store count
  unchanged); `JobStore::evict_locked` drops oldest terminal records beyond the cap,
  never active ones. Owner **02** (bounds), **01** (retention).

#### [HIGH] T-87 Use-after-free: job body outliving its per-request runtime
- Vector: a REST per-request `CommandRuntime` is destroyed while its submitted job
  still runs on a worker; a body capturing `CommandRuntime&`, `CommandRegistry&` or
  `ServerConfig&` dangles (`pair_commands.cpp`, `command_runtime.cpp`).
- Impact: UAF / crash / data corruption on the worker thread.
- Mitigation (testable): bodies capture **only** `std::shared_ptr` copies
  (`LinkCommandService`, `ILinkLister`) and plain values (lifetime rule, 20);
  20's test destroys the runtime, then opens the gate and asserts `succeeded` under
  ASan. Owner **20** (rule + test), **08/10** (body capture).

#### [MEDIUM] T-88 Non-cooperative / long-running body blocks shutdown
- Vector: `shutdown()` joins workers unconditionally (no portable timed join); a
  body that never polls `cancel_requested()` hangs the process on exit (03).
- Impact: hung shutdown / drain timeout for `serve-stdio` EOF and server SIGTERM.
- Mitigation (testable): every body polls the cancel flag **once per row/page**
  (08 import loop, 10 export loop); shutdown does `wait_idle(timeout)` -> `cancel_all()`
  -> join; 03/20 assert `active_count()==0` after cooperative drain and a bounded
  process exit. Owner **02/03** (contract), **08/10** (poll placement).

#### [MEDIUM] T-89 Shutdown / drain races and double-shutdown
- Vector: concurrent `submit`/`cancel`/`finish`/`shutdown`; inconsistent lock order
  between `m_mutex` and the `JobStore` mutex (`job_runner.cpp`).
- Impact: deadlock, double-join, thread leak, `std::terminate` on exit.
- Mitigation (testable): documented lock order (`m_mutex` before store mutex, never
  reverse); idempotent `shutdown`/`cancel_all`; destructor calls `shutdown`; 02/03
  run `--repeat until-fail:20` and ThreadSanitizer where available; no `detach`,
  no `std::terminate`. Owner **03**.

#### [LOW] T-90 Cancellation correctness / partial-result integrity
- Vector: cancel of queued vs running vs unknown job; partial results after cancel.
- Impact: lost/incorrect partial state; cancel of a finished job mutating it.
- Mitigation (testable): queued -> `cancelled` immediately, body never run; running ->
  flag set, `result_json` partial counts preserved; terminal -> no-op returns final
  record; unknown -> `nullopt` (02 cases). Owner **02**.

### Dry-run contract (carry-forward from 01.0 T-21)

#### [MEDIUM] T-91 `link.import` dry-run must not use the async job path  *(SPEC GAP)*
- Vector: spec 08 treats `options.dry_run` only as a flag inside the worker body and
  still returns a `job` envelope, contradicting the 01.0 T-21 contract (dry-run runs
  **synchronously on the request thread** with a `NoopJobContext` that cannot cancel,
  no mutation, bounded work).
- Impact: inconsistent dry-run semantics across commands; a dry-run that occupies a
  worker and is cancellable mid-validation yields ambiguous partial state; validate
  path diverges from the authoritative contract.
- Mitigation / amendment (testable): spec 08 must state that when `dry_run` is set the
  command executes synchronously (returns `result`, not a `job`), builds its body with
  `NoopJobContext` (`cancel_requested()==false`), performs **no** `CreateLink`
  persistence, and stays bounded by `kMaxImportRows`/file-size caps; test both the
  no-mutation and no-cancel properties (01.0 T-21). Owner **08**.

### Job visibility / authorization (subtasks 05, 11, 21)

#### [MEDIUM] T-92 No per-principal job ownership (cross-caller visibility/cancel)
- Vector: `job.get`/`job.list`/`job.cancel` operate over one process-wide runner; any
  authorized caller sees/cancels **any** job (05, 11); jobs carry no owner in V1.
- Impact: in a future multi-user deployment a `User` could observe/cancel another
  principal's job. In V1 the trust domain is single (REST gate: read-any /
  write-loopback-admin; stdio/CLI = one local operator), so impact is contained.
- Mitigation (testable): REST `job.cancel` is `write` -> `admin`+loopback only, `user`
  cancel -> 403 and job keeps running (11 test); documented V1 limitation; **forward
  constraint**: 0002 must add owner filtering before multi-user sessions. Owner **05/11**.

#### [LOW] T-93 Sequential `j-<n>` ids are not an authorization capability
- Vector: ids are guessable; a future design might treat them as unguessable handles.
- Impact: none in V1 (job.list already enumerates all jobs to a read caller); becomes
  a flaw only if 0002 relies on id secrecy for per-owner access.
- Mitigation: record constraint - ids are correlation handles, never an authz check;
  0002 must authorize by owner, not by id knowledge. Owner **01/05**.

#### [MEDIUM] T-94 `jobs` table (`db.rows`) must expose metadata only
- Vector: `make_jobs_table_source` over `JobRunner::list` (21); a naive row could
  include `args`, `args_digest`, `result_json` (a full inline link-table export!) or a
  failure **message** (may echo caller-chosen arg names).
- Impact: information disclosure of secrets/PII/args to any `read` caller via
  `db.rows {"table":"jobs"}`.
- Mitigation (testable): fixed literal column list (`id, command, state, done, total,
  error_code, created_at, finished_at`); `error_code` only, never the message; marker
  strings planted in args/result never appear in any row (21 test); values JSON-escaped.
  Owner **21**.

### Pair file access (subtasks 06-10)

#### [HIGH] T-95 Arbitrary server-file read/write via `path`  *(SPEC GAP)*
- Vector: `link.import`/`link.export` accept a server-side `path`. The remote-refusal
  is a **blocklist** - factory checks `transport == "rest"` (08/10) - while
  `PathPolicy.allow_paths` **defaults to `true`** (07, 20). The REST per-request runtime
  (04.0/02) is not required by the specs to set `allow_paths=false`, so the sole control
  stopping a remote caller from naming an arbitrary server path is one string compare,
  and any future remote transport that neither is named `"rest"` nor disables paths
  inherits full filesystem access.
- Impact: remote arbitrary file read (exfiltrate secrets/config) and create-new write.
- Mitigation / amendment (testable): make it an **allowlist** - add an explicit
  "local operator / filesystem-allowed" capability to `CallerContext`/`PathPolicy`
  that defaults to **deny**; only `cmd`/`tui`/`serve-stdio` composition sets it true;
  the import/export factory refuses `path` with `unsupported` unless that capability is
  present, independent of transport name; and `build_command_runtime` for REST must set
  `file_paths.allow_paths=false`. Keep the existing per-rule path checks of 07
  (canonicalize, UNC/device reject, regular-file-only, size caps, create-new). Owner
  **07** (policy), **08/10** (factory), **20** (REST runtime default).

#### [MEDIUM] T-96 `--path-root` jail escape via TOCTOU / in-root symlink  *(SPEC GAP)*
- Vector: spec 07 canonicalizes and compares component-wise, but accepts TOCTOU
  "for local operators" and resolves symlinks before the regular-file check; with
  `--path-root` the producer (e.g. a webview sidecar) is only semi-trusted and can swap
  a validated in-root path for a symlink pointing outside between check and open.
- Impact: read/write outside the confinement the operator believed `--path-root`
  enforced.
- Mitigation / amendment (testable): for the rooted case, open with `O_NOFOLLOW` on the
  final component (or re-`weakly_canonical` the opened fd/path and re-assert the root
  prefix after open), or explicitly document that `--path-root` is a convenience
  confinement and **not** a boundary against a hostile in-root writer. Add a symlink-swap
  test for the rooted path. Owner **07**.

#### [MEDIUM] T-97 Import parse / size resource exhaustion
- Vector: huge file, huge single line, huge row count (06/07/08).
- Impact: memory/CPU DoS on a worker.
- Mitigation (testable): `kMaxImportFileBytes=64MiB`, `kMaxImportLineBytes=16384`,
  `kMaxImportRows=100000`; `read_bounded_line` drops the remainder of an over-long line
  without storing (bounded memory, re-checked while reading as the file grows); row cap
  fails the job with partial counts (plain text, no decompression -> no bomb). Owner
  **06/07/08**.

#### [LOW] T-98 CSV formula injection on export
- Vector: CSV cells beginning `= + - @` executed by a spreadsheet opening the export.
- Impact: none in practice - CSV emits only `full_url,slug`; targets are always
  `http(s)://...` and `isValidSlug` is `^[A-Za-z0-9]...`, so no cell can start with a
  trigger; fields with `, " CR LF` are quoted (10). (NDJSON carries `metadata`/`tags`
  but is JSON, not formula-evaluated.)
- Mitigation (testable): property check over the slug alphabet + generator asserts no
  cell starts with `= + - @` (07.0/20). Owner **10**.

#### [MEDIUM] T-99 Export clobbers an existing server file
- Vector: writing to an attacker/operator-chosen `path` (10).
- Impact: destruction/overwrite of an arbitrary existing file.
- Mitigation (testable): create-new only - target must not exist (`invalid_field`),
  write to `<path>.tmp-<pid>-<n>` opened exclusively, `commit` renames atomically,
  abort/destructor removes temp; two racing sinks -> exactly one commits (07 tests).
  Owner **07/10**.

#### [MEDIUM] T-100 Partial/destructive import auditability (repudiation)
- Vector: import is non-atomic (rows persist up to a failure/cancel); `on_conflict=
  overwrite` destructively replaces `target_url` of existing links (09); audit emits
  one `job_accepted` line per job with no per-row values (C6).
- Impact: no forensic record of which slugs were overwritten/created to what.
- Mitigation (testable): overwrite goes through the single `ReplaceLinkTarget` service
  method (same normalize/SSRF path); the job result (counts incl. `overwritten`) is
  retained and retrievable via `job.get`; one audit line carries the job id. Accept the
  C6 value-free constraint; confirm count-level audit is sufficient with app-architect.
  Owner **09/20**.

#### [MEDIUM] T-101 Bulk import bypasses the per-peer create throttle (T-75)
- Vector: `link.import` creates many links via `CreateLink` directly, not through
  `apply_create_throttle` (04.0 T-75, keyed per HTTP peer).
- Impact: a caller creates thousands of links in one request, bypassing the public
  create-rate limit.
- Mitigation (testable): `link.import` is `write`; over REST the gate runs it only as
  loopback `admin`, and `path` is unsupported + inline `data` is capped at
  `max_request_body_bytes` (~1k rows/request); `User` -> `not_authorized` (08 test).
  Over stdio/CLI the caller is the local operator. Accepted on that basis; add the
  explicit "import is throttle-exempt and reachable only with `write`" note to spec 08.
  Owner **08**.

### NDJSON stdio transport (subtasks 13-15, 17)

#### [MEDIUM] T-102 stdout pollution corrupts the wire / leaks logs
- Vector: any log/banner/prompt written to `std::cout` interleaves with response
  envelopes (`logger.cpp` has a `LogSink::Stdout`; `LinkService` logs).
- Impact: protocol corruption and possible secret/log disclosure into the stream the
  parent consumes as data.
- Mitigation (testable): 17 forces `LogSink::Stderr` regardless of config, `Stdout`
  never allowed, `sync_with_stdio(false)`; the session writes envelopes only (C2) and
  `write_response` asserts no raw newline; 18 "log-to-stdout bug fails the test". Owner
  **17/14**.

#### [MEDIUM] T-103 Unbounded stdin line memory DoS
- Vector: a 10 MiB single line with no `\n` (13).
- Impact: unbounded buffering / OOM.
- Mitigation (testable): `NdjsonLineReader`/`read_bounded_line` cap at
  `max_request_body_bytes` (64 KiB), `too_long` consumes and drops the rest with
  bounded capacity; 13 asserts `line.capacity()` stays small. Owner **13/07**.

#### [LOW] T-104 Framing confusion / request-id collision
- Vector: partial lines, interleaving, a client sending `id:"srv-5"` colliding with the
  session counter (14).
- Impact: response/request mismatch.
- Mitigation (testable): one content line -> exactly one response line, strict order,
  single-threaded; id echoed (not used for routing); best-effort recovery via the
  sanctioned `scan_object` (<=64 chars) else `srv-<n>`; no pipelining. Owner **13/14**.

#### [LOW] T-105 Backpressure stall
- Vector: a parent that never reads stdout blocks `flush` (14).
- Impact: session stalls (bounded - single-threaded, no further reads; jobs bounded).
- Mitigation: documented (parent owns the pipe); no unbounded buffering. Owner **14/15**.

#### [MEDIUM] T-106 EOF/shutdown drain races and SIGPIPE kill
- Vector: closed stdout -> SIGPIPE kills the process mid-job; EOF drain racing running
  jobs; no SIGINT/SIGTERM handler (15/17).
- Impact: abrupt termination; lost drain; broken-pipe crash.
- Mitigation (testable): POSIX `SIGPIPE` ignored so closed stdout -> stream failure exit
  4; EOF -> `wait_idle(drain_timeout)` -> `cancel_all()` -> grace, exit 0; in-memory jobs
  on hard signals are a documented non-goal (committed rows persist). 15/18 assert exit
  codes and no listener. Owner **15/17**.

### serve-stdio caller identity (subtasks 15-17)

#### [MEDIUM] T-107 Default `Admin` + full filesystem access for the local operator
- Vector: `serve-stdio` grants `ControlSet::Admin` and `allow_paths=true` (no root) by
  default; a parent that exposes stdin to a less-trusted producer (webview sidecar)
  hands that producer full read/write over links and arbitrary server files.
- Impact: privilege/filesystem exposure when the "local operator" assumption is weaker
  than reality.
- Mitigation (testable): `--read-only` downgrades to `User`; `--no-file-paths` and
  `--path-root` restrict `path`; mutually-exclusive combination rejected (16); decision
  Q6 recommends them for sidecars. **Document prominently** (15/17/19) that the secure
  posture for an untrusted producer requires these flags; see also T-95 default-deny.
  Owner **15/17/19**.

### Audit & memory retention (subtasks 01, 05, 10, 20)

#### [MEDIUM] T-108 Job audit records acceptance only, not outcome
- Vector: only `job_accepted` (with id, no args) is sent to the audit sink at submit;
  terminal state is a `job_finished` **log** line, not an audit record (02/20).
- Impact: the audit trail shows a destructive import/overwrite was accepted but not its
  result; a failed/cancelled outcome is not independently audited.
- Mitigation (testable): outcome retrievable via `job.get` (retention 256) and present
  in stderr logs owned by the parent (D14); confirm count-level granularity is
  sufficient. Owner **20/05**.

#### [MEDIUM] T-109 Inline export result retained in memory and re-readable
- Vector: an inline `link.export` result (up to `kMaxInlineExportBytes`=1 MiB, a full
  link-table slice) is stored in `JobRecord::result_json` and retained for up to
  `max_retained_jobs`=256 jobs (01/10).
- Impact: ~256 MiB worst-case memory DoS; the exported link data lingers and any later
  `read` caller in-process can re-read it via `job.get`.
- Mitigation (testable): bounded by the 1 MiB inline cap x 256 retention (count-based
  eviction); over REST the same data is already `read`-tier (no escalation); file-mode
  export streams page-by-page and stores no data in the record. Consider trimming large
  `result_json` from retained records. Owner **01/10**.
