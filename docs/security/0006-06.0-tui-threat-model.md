# Threat Model - Milestone 0006 Task 06.0 Terminal UI - 2026-11-18

Design-time (pre-implementation) STRIDE-lite review and **standing input for every
implementation brief** in Task 06.0 (21 subtasks under
`docs/roadmap/0006-unified-command-model-and-tui/06.0-tui/`), ADR 0003, and
plan.md "Shared contracts" C1-C11 (esp. C5/C6/C7/C8/C11). No 06.0 product code
exists yet. T-IDs start at **T-110** (01.0 = T-01..T-22, 02.0 = T-30..T-41,
03.0 = T-50..T-59, 04.0 = T-60..T-85, 05.0 = T-86..T-109). Findings
cross-reference the earlier models rather than restate them.

Carry-forward honoured here: 01.0/04 LOW (`commands::parse_response` is lenient -
ignores unknown top-level keys, no `ok`/payload cross-check) -> T-113; 05.0 T-95/
T-96/T-99 (path capability default-deny, `--path-root` jail, export clobber) ->
T-118; 05.0 T-102 (stdout pollution) -> T-119; 05.0 T-107 (local operator = Admin
by default) -> T-115; 05.0 split-store bug (serve-stdio built a runtime over an
inactive `LinkBackendHandle`) -> T-114.

## Assets & trust boundaries

- **The operator's terminal emulator.** The single most valuable asset here and the
  one new to this task. Everything the TUI prints is interpreted by a terminal that
  honours ANSI/CSI/OSC/DCS control sequences. Stored link/row/job data flows
  *untrusted input -> command result JSON -> FTXUI `text()` cell -> `Screen::ToString`
  -> terminal*. This boundary did not exist for the REST/CLI/stdio adapters (which
  emit inert JSON to a pipe); the TUI is the first adapter that renders stored data
  into an interpreting sink.
- **Caller identity.** `CallerContext{principal="local-operator", Admin}` (or `User`
  under `--read-only`), synthesized by `tui_entry.cpp` and trusted by
  `registry.execute` as the sole authz root (01.0 T-11, C7). The TUI must obtain its
  registry from `composition::build_command_runtime` over the **active** backend
  handle (C11) - never a second/inactive one.
- **Server filesystem** (via `path` on `link.import`/`link.export`) - a
  local-operator capability (05.0 T-95).
- **Secrets at risk:** DSNs, TLS keys, `analytics_client_hash_salt`, token/password
  hashes (never browsable: C6 allowlist in `db.*`/`system.info`); the audit log file
  the TUI opens (D14).
- **The in-process command registry / job runtime / worker threads** - shared,
  process-wide (C11); jobs outlive the screen that launched them (05.0 boundary).

## Findings

### Surface 1 - Terminal rendering of untrusted stored data (the new boundary)

#### [CRITICAL] T-110 Terminal escape / control-sequence injection from stored data
- **Vector / evidence:** No subtask defines a central terminal-control sanitizer.
  `text_fit` (09) does UTF-8 **width/truncation only**; the one sanitization in the
  task is `10-table-view.md:73` "cell with newline/tab sanitised to a space" - which
  covers neither `ESC`(0x1B)/`CSI`/`OSC`/`DCS`, C1 controls, bidi overrides
  (U+202A-202E, U+2066-2069), nor zero-width (U+200B-200D, U+FEFF), and is scoped to
  the table body only. Form widgets (08), toast/confirm + `[d]etails` raw envelope
  (06), result viewer `pretty_print` (11), link-detail rows (13), row-JSON (14), job
  outcome/`error` text (16) all render server strings with no sanitizer named. The
  render harness `render_to_text` (01) strips FTXUI's *own* SGR output but does **not**
  neutralise control bytes sitting inside a data cell - and goldens use benign
  fixtures, so nothing catches it. Even though the URL validator now rejects control
  bytes (CWE-113 fix, 05.0), **legacy rows, `metadata`/`tags`/`campaign`, slugs on
  pre-fix rows, and job failure `what()` text may still contain them**, and
  `db.rows`/`click_events` expose `referrer`/`user_agent`-derived fields.
- **Impact:** A hostile row (planted via REST/import by a lower-privileged actor,
  rendered later in the Admin operator's terminal) can repaint/spoof the screen,
  emit **OSC-52 to overwrite the system clipboard**, emit OSC-8 hyperlinks, push/pop
  the window title, enable mouse/bracketed-paste modes, or on vulnerable terminals
  reach command execution (CWE-150 improper neutralization of escape sequences;
  CWE-838). A **bidi override in a slug** can make the confirm dialog (D10) display a
  different slug than the bytes the operator types, causing deletion of the wrong
  link. This crosses the untrusted-data -> privileged-terminal boundary with no
  mitigation in the model.
- **Mitigation (testable):** Add `sanitize_for_terminal(std::string_view) ->
  std::string` to `text_fit` (09, model lib, no FTXUI) that, applied **before width
  fitting**: drops/replaces all C0 except none-needed, all C1, `ESC` and any
  CSI/OSC/DCS/APC/PM/SOS introducer and payload, DEL, bidi-control and
  zero-width/BOM code points (-> U+FFFD or stripped), and bounds each field to a
  max display length. Route **every** screen render sink through it (09->10 cells,
  08 field echo, 06 toast title/body/details, 11 pretty_print output, 13 rows, 14
  row JSON, 16 outcome/error). Confirm-token compare stays on raw bytes while the
  displayed token is sanitized. Add a shared hostile-data fixture (`ESC[2J`, `OSC 52`,
  `U+202E`, `U+200B`, 64 KiB field) and one golden/assert per sink proving the bytes
  never reach the rendered grid. The TUI must itself **never emit OSC-52** (08 keeps
  clipboard out of scope - keep it that way). Owner: **09** (helper) + **10, 08, 06,
  11, 13, 14, 16** (apply + fixture).

### Surface 2 - In-process client trust boundary & caller identity

#### [MEDIUM] T-114 Registry built over an inactive backend handle (split-store repeat)
- **Vector / evidence:** `tui_entry.cpp` (19) calls `build_command_runtime(config)`
  then `InProcessClient(*runtime.registry, caller)`. serve-stdio once built a runtime
  over an inactive `LinkBackendHandle` (fixed ba2d150), showing two live stores and a
  TUI that writes to one and reads another.
- **Impact:** Confirmed deletes/updates appear to fail or silently diverge; an
  operator could believe a link is gone while the redirect path still serves it.
- **Mitigation:** 19 must take the registry only from `build_command_runtime` placed
  **after** `InitLinkBackend` (02.0/12), never construct its own registry/runner/
  handle (C8/C11), and the 19 boundary test asserts no `CommandRegistry`/`JobRunner`
  construction in `tui_entry.cpp`. Add a smoke assert: create via TUI client, read
  back via the same client, see the row. Owner: **19**.

#### [MEDIUM] T-115 Local operator defaults to Admin; no authentication prompt
- **Vector / evidence:** 19 synthesizes `ControlSet::Admin` for any local `tui`
  invocation (ADR 0003 decision Q6); `--read-only` is opt-in. Same posture as 05.0
  T-107.
- **Impact:** Anyone who can run the binary on the host gets full read/write/manage
  over the store. Accepted for a local-only tool; no network listener (C5).
- **Mitigation:** Documented; `--read-only` available; per-user sessions carried to
  Milestone 0002. The auth broker stays local-only (C7). Owner: **19** (doc),
  app-architect (0002 carry).

### Surface 3 - Read-only mode completeness & mutation safety

#### [MEDIUM] T-116 Mutating paths that bypass the capability/confirm choke points
- **Vector / evidence:** 18 centralises enable/disable in `CapabilityModel` and 06/08
  route mutations through `run_mutation` + `ConfirmPolicy`. Two paths are easy to
  miss: the palette **raw-JSON args** escape hatch (`Ctrl-J`, 11) and a **no-arg
  mutating generic command** that "skips the form and goes straight to confirm/
  execute" (11 step 3). The 18 matrix test enumerates *screens*, not these two
  entry variants explicitly.
- **Impact:** A read-only session could appear to send a write; or a mutation could
  reach `AsyncCaller::submit` without a confirm. Server-side `AccessGuard` still
  denies writes for `ControlSet::User` (C7, defence in depth), so this is
  presentation-integrity, not an authz break.
- **Mitigation:** 18's `18_readonly_matrix_test` must drive the palette raw-JSON path
  and a no-arg mutating command, asserting zero write/migrate requests and that every
  mutation still passes `ConfirmPolicy`. Owner: **18** (+ **11**).

#### [LOW] T-117 `--yes` skips the typed-slug confirmation for `link.delete`
- **Vector / evidence:** ADR 0003 rule 4 "skippable with `--yes`"; 06 step/risks.
- **Impact:** Scripted/`--yes` sessions delete without the typed-slug guard. Dry-run
  import is still treated as mutating (safe). `--yes` never relaxes permission (read-
  only still denies - 18).
- **Mitigation:** Documented in the TUI guide; read-only sessions never reach the
  confirm. Owner: **06/18** (doc).

### Surface 4 - File-path entry in import/export

#### [MEDIUM] T-118 `path` arg gives the local operator arbitrary server read/write
- **Vector / evidence:** 15 passes `path` to `link.import`/`link.export`; the TUI is a
  local-operator mode, so `PairFileOptions.allow_paths` opts in (05.0 T-95). Export
  `path` raises the permission to `write` (read-only denies it - 15/18). The TUI does
  no client-side path validation (good: avoids TOCTOU, 15 step 7). Residual: tilde/
  relative paths, in-root symlink/TOCTOU (05.0 T-96), export file clobber (05.0 T-99).
- **Impact:** Operator-scoped file read/write within `--path-root`; already bounded
  server-side by `O_EXCL`/`O_NOFOLLOW` (05.0 mitigations).
- **Mitigation:** 15 must (a) render the path field disabled with the
  `not_authorized` reason in read-only mode, (b) surface the server's path-capability/
  `--path-root` denial as a clear toast, and (c) state export never silently
  overwrites (server `O_EXCL` returns a conflict the screen shows). No new TUI
  filesystem logic. Owner: **15** (cross-ref 05.0 T-95/96/99).

### Surface 5 - Logging while the TUI owns the terminal

#### [MEDIUM] T-119 Log output corrupting the screen / audit-log exposure
- **Vector / evidence:** An uninitialised logger defaults to `enabled, Stderr`
  (verified `logger_factory.cpp`), so the `LoggerAuditSink` would corrupt the alt-
  screen. 19 fixes screen-corruption by forcing a `File` sink before
  `build_command_runtime` and refusing to start if the file can't open. Not specified:
  the audit file's **permissions** and that its lines carry no secret arg values.
- **Impact:** Screen corruption (mitigated); a world-readable `./url_shortener-tui.log`
  could leak audit metadata.
- **Mitigation:** 19 must create the log file `0600` and the review must confirm
  audit lines carry no argument values (C6). Owner: **19**.

### Surface 6 - Async worker + PostEvent lifetime

#### [LOW] T-120 Use-after-free when the UI is torn down with a call in flight
- **Vector / evidence:** 03 guards completions with a `shared_ptr<atomic<bool>>
  m_alive`, joins workers in the destructor, and suppresses cancelled tokens; 16's
  `PollTicker` likewise.
- **Impact:** UAF / handler running against a destroyed screen - mitigated by design.
- **Mitigation:** Keep the 03 destructor-in-flight and TSan tests; handlers capture
  `weak_ptr`/tokens, never raw screen pointers (03 constraint). Owner: **03/16**.

### Surface 7 - Resource limits / DoS

#### [LOW] T-121 Unbounded rendering, polling, or result size
- **Vector / evidence:** Bounds already present: `json_view` 8 MiB cap (02); result
  viewer lazy at 10,000 lines (11); inline export display truncated at 64 KiB (15);
  `job.list limit:50`, poll backoff 1->5 s, skip-tick-if-in-flight, stop when hidden
  (16); `db.rows limit 1..500` (14); `link.list` paged 20 (12); inline import <=
  `max_inline_bytes` (15/19).
- **Impact:** Largely bounded; residual cost is wide-table re-layout per frame.
- **Mitigation:** Keep the caps as tested invariants; `truncate_to_width` must be
  O(width) not O(field). Owner: **09/14/16**.

### Surface 8 - FTXUI dependency supply chain

#### [MEDIUM] T-122 FTXUI pinned by a movable tag, not a fixed commit/hash
- **Vector / evidence:** 01 uses `FetchContent_Declare(... GIT_TAG <pinned>
  GIT_SHALLOW TRUE)`; a Git tag can be re-pointed upstream, and `GIT_SHALLOW` fetches
  whatever the tag currently references.
- **Impact:** A compromised or re-tagged upstream injects code into the build (supply-
  chain, CWE-494/CWE-829).
- **Mitigation:** Pin the exact **commit SHA** (not only the tag) in
  `FetchFTXUI.cmake`, or use a release tarball with `URL_HASH SHA256=...`; record the
  SHA + verification date in ADR 0003 Decision 1; keep the vcpkg feature behind the
  checked-in baseline. Include FTXUI as a `SYSTEM` target (already planned). Owner:
  **01**.

### Surface 9 - Crash / terminal-state restoration & capability abuse

#### [MEDIUM] T-123 Raw mode / alt-screen / mouse tracking left on after exception or signal
- **Vector / evidence:** 19 step 5 and 04 risks require restoring the terminal "on all
  exit paths including exceptions" via RAII + `catch(...)`, but neither makes it a
  *tested* requirement, and SIGTERM/SIGHUP handling for `tui` is unspecified (FTXUI
  owns SIGINT only).
- **Impact:** A crash leaves the shell in raw mode / alt-screen / mouse-reporting
  (SET 1000/1006) / bracketed-paste - a broken, partially input-capturing terminal
  (availability + minor integrity).
- **Mitigation:** Make teardown a tested requirement: a forced-exception path asserts
  the `ScreenInteractive` destructor/RAII restore runs; ensure SIGTERM also restores
  (install a minimal handler or document FTXUI's behaviour); disable mouse/bracketed-
  paste on exit. Owner: **04/19**.

#### [LOW] T-124 Mouse tracking enabled despite being an ADR non-goal
- **Vector / evidence:** Mouse is an ADR 0003 non-goal; FTXUI may still enable mouse
  reporting by default on `Fullscreen()`.
- **Impact:** Escape-sequence noise if not disabled on exit (tie to T-123).
- **Mitigation:** Confirm at pin time whether `Fullscreen()` enables mouse; disable if
  the ADR non-goal is to hold; cover in the T-123 restore test. Owner: **04**.

### Surface 10 - Information disclosure on screen

#### [LOW] T-125 `equivalent_cli` footer / `[d]etails` raw envelope disclosure & paste-safety
- **Vector / evidence:** 08/06 show the full request JSON (`equivalent_cli`) and the
  raw response envelope. Args hold no secrets (C6). The CLI line must shell-quote so a
  copy-pasted command cannot break out of quoting.
- **Impact:** Low; no secret in args. A mis-escaped single-quote in a pasted line is a
  shell-quoting hazard on the operator's own shell.
- **Mitigation:** `equivalent_cli` single-quote-escapes payloads (06 step 4, tested
  with quotes/backslashes); never echoes a value `system.info`/handlers would redact.
  Owner: **06/08**.

#### [LOW] T-126 Settings screen rendering a non-allowlisted field
- **Vector / evidence:** 21 renders exactly the deserialized `system.info`
  `shortener` block, which 03.0/17 restricts to non-secret fields (no `tls`, no
  `analytics_client_hash_salt`, no ports/DSNs - C6).
- **Impact:** None while 21 adds no field of its own; mitigated server-side.
- **Mitigation:** 21 renders only the deserialized struct and issues only
  `system.info` (asserted request set); once 03.0/17's secret test passes there is
  nothing to leak. Owner: **21** (relies on **03.0/17**).

### Surface 11 - Envelope strictness carry-forward

#### [LOW] T-113 Lenient response handling hides malformed/ambiguous envelopes
- **Vector / evidence:** `commands::parse_response` is lenient (01.0/04 LOW: ignores
  unknown top-level keys, no `ok`/payload cross-check); `json_view` getters (02)
  silently return `nullopt` on malformed input. `InProcessClient` returns the typed
  `CommandResponse` directly (lower risk), but a future `RemoteClient` parses the
  wire.
- **Impact:** A malformed/ambiguous envelope (e.g. `ok:true` with an `error` object)
  could render as a success toast - operator misled.
- **Mitigation:** The client seam should treat a response with both/neither of
  `result`/`error`, or `ok` disagreeing with their presence, as an `internal`-style
  error toast; add a `02_in_process_client_test` case. Alternatively tighten
  `parse_response` (01.0 owner). Owner: **02** (cross-ref 01.0/04).

## Verdict: BLOCK

**T-110 is CRITICAL**, so this standing-input review is a merge BLOCK: no 06.0
render subtask (08, 10, 11, 13, 14, 16) may merge until the centralized
`sanitize_for_terminal` SPEC GAP is folded into subtask 09 (and the apply-at-sink +
per-sink hostile-data assertion into each render subtask). The merge-blocking hook /
human reviewer must keep any TUI render code that prints unsanitized stored data out
of `master`.

The other findings are PASS_WITH_FOLLOWUP: the six MEDIUM/LOW SPEC GAPs
(T-122, T-123, T-119, T-118, T-116, T-113) must be folded into the owning subtask
specs before those subtasks implement, and each per-threat mitigation must appear as
a named test assertion. Fixes go to `cpp-expert`; regression/fixture tests to
`testing-expert`; the sanitizer contract (T-110) and the FTXUI pin policy (T-122) to
`app-architect`. Forward constraints to Milestone 0002: per-user sessions /
non-Admin local roles (T-115).
