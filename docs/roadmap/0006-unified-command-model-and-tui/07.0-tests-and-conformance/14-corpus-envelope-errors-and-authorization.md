## Objective

Cover every catalog error code that is produced by the registry itself rather
than by a command, plus the read-only/`not_authorized` behavior for each
mutating command, so envelope validation is identical on all transports.

## Dependencies

- Catalog section 1 (request fields, error table).
- Capabilities: `raw_request` is carried by `direct`, `rest_generic`, `stdio` only (subtask 05 table); other transports skip these steps by capability.

| Case | Input | Expected |
|---|---|---|

Also: `envelope_extra_top_level_key` (unknown key ignored or rejected - pin
01.0's decision; catalog says only `args` unknown keys are rejected),
`envelope_nul_and_control_chars_in_string` (arg value with `\u0000` ->
`invalid_field`, process stays healthy: the case ends with a `command.list`
step that must succeed).

**41_authorization.json (generated + hand-written):**

- Hand-written (6): `authz_user_can_read_link_get`, `authz_user_denied_link_create` (`not_authorized`), `authz_user_denied_link_import`, `authz_user_denied_job_cancel`, `authz_user_can_list_jobs`, `authz_denied_step_has_no_side_effect` (admin creates, user attempts update -> `not_authorized`, admin `link.get` shows unchanged).
- Generated (matrix): `tools/conformance_gen_authz.py` reads `command.list` from the binary and emits one case per descriptor with `perm != read`: `authz_matrix_<command>` where the step runs the command with minimal valid args as `user` and expects `not_authorized`; the generated file `42_authorization_matrix.json` is **committed** and re-generated by subtask 15's gate (CI fails if regeneration changes it).

`not_authorized` precedes argument validation: a `user` calling `link.create` with
invalid args must get `not_authorized`, not `invalid_field` (case
`authz_check_precedes_validation`; order per ADR 0002: authorize, then ArgSpec check).
Unknown command by `user` is still `unknown_command`.

## Implementation steps

1. Write `40_` and `41_` by hand; each raw envelope case lists `transports.skip` for non-raw transports only when the capability mismatch would not be auto-skipped (it is auto-skipped; no entry needed).
2. Implement `tools/conformance_gen_authz.py` (stdlib; spawns `url_shortener cmd command.list`; picks minimal args from `ArgSpec` required fields using type defaults: string `"x"`, bool true, int 1, enum first value).
3. Commit generated `42_authorization_matrix.json`.

## Constraints

- Error code assertions only; never message text.
- The generator never writes outside `tests/conformance/commands/`.
- Matrix cases use dummy args that would be valid, so a failure means authz, not validation.

## Success criteria

1. Error codes `invalid_envelope`, `unknown_command`, `invalid_field`, `unsupported`, `not_authorized` each appear in this group; `busy` and `job_cancelled` in 13; storage/internal and the url/slug codes in 11.
2. Matrix has one case per non-`read` descriptor and CI fails when a new mutating command is added without regenerating.
3. All cases pass on every capability-eligible transport.

## Out of scope / risks

- `storage_failure` / `internal` need fault injection; covered by unit tests in 01.0/03.0, listed in the coverage gate as "unit-covered" (see subtask 15).
- Risk: role for REST transports (subtask 08 decision) may make `authz_*` cases skip there; subtask 19 covers REST `not_authorized` separately.
