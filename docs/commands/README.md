# Command Catalog

> **Status:** Proposed (design of Milestone 0006; normative once ADR 0002 is accepted).
> Generation split (decision-log "Open decisions"): the generator of Task 01.0
> (subtasks 11-12, `tools/command_catalog_dump`) owns **only** the block
> `### 3.7 Generated command reference`, the way [`docs/api/README.md`](/docs/api/README.md)
> is generated from `RouteRegistry`. Sections 1-6 stay hand-written prose and
> are guarded against drift by Task 07.0 subtask 16 (headings, argument tables
> and the error table are compared with the registry and the error table of
> Task 01.0 subtask 02).

Every operation available through REST, CLI, TUI, stdio and any future IPC
transport is one of the commands below. A command is **one definition and one
implementation**; transports only differ in how the JSON goes in and out. See
[ADR 0002](/docs/adr/0002-unified-command-model.md) for the rationale and
[ADR 0003](/docs/adr/0003-tui-framework-and-architecture.md) for the TUI.

## 1. Envelope

### Request

```json
{
  "v": 1,
  "id": "c-42",
  "command": "link.create",
  "args": { },
  "options": { "dry_run": false, "async": false }
}
```

| Field | Type | Required | Meaning |
|---|---|---|---|
| `v` | integer | yes | Envelope version. Only `1` is defined. |
| `id` | string, <= 64 chars | no | Client correlation id; echoed in the response. Generated by the server if absent (`srv-<n>`). |
| `command` | string | yes | Dotted command name from section 3. |
| `args` | object | per command | Validated against the command's argument table. Unknown keys -> `invalid_field`. |
| `options.dry_run` | boolean | no, default `false` | Validate and authorize, do not mutate. Supported only where the catalog says so; elsewhere `unsupported`. |
| `options.async` | boolean | no, default `false` | Run an `async_capable` command as a job. |

### Response

Success:

```json
{ "v": 1, "id": "c-42", "ok": true, "result": { } }
```

Accepted as a job:

```json
{ "v": 1, "id": "c-43", "ok": true, "job": { "id": "j-9", "state": "queued" } }
```

Failure:

```json
{ "v": 1, "id": "c-42", "ok": false,
  "error": { "code": "slug_conflict", "message": "slug already exists" } }
```

Exactly one of `result`, `job`, `error` is present. `error.message` is for
humans and may change; `error.code` is the stable contract.

### Error codes

| Code | Meaning | HTTP | CLI exit | Resource-route `error` string (legacy) |
|---|---|---|---|---|
| `invalid_envelope` | Request is not valid JSON / missing `command` / bad `v` | 400 | 2 | n/a (generic endpoint only) |
| `unknown_command` | No such `command` | 404 | 2 | n/a |
| `invalid_field` | Unknown/ill-typed/missing arg | 400 | 2 | `invalid_request` (plus today's per-field codes, see below) |
| `invalid_url` | Target URL malformed **or** blocked (SSRF); intentionally indistinguishable | 400 | 2 | `invalid_url` |
| `invalid_slug` | Slug malformed | 400 | 2 | `invalid_slug` |
| `reserved_slug` | Slug is on the reserved list | **409** | 2 | `reserved_slug` |
| `slug_conflict` | Slug already used | 409 | 3 | `slug_conflict` |
| `not_found` | Link / job / table not found | 404 | 1 | `not_found` |
| `not_authorized` | Caller's role lacks the command's permission | 403 | 5 | n/a |
| `unsupported` | `dry_run`/`async` not supported for this command; feature placeholder | 501 | 2 | n/a |
| `busy` | Job queue full | 503 | 4 | n/a |
| `job_cancelled` | Job ended by `job.cancel` (appears in `job.get`) | 200 | 4 | n/a |
| `storage_failure` | Backend failure | 500 | 4 | `repository` |
| `internal` | Unexpected failure | 500 | 4 | `internal_error` |

The codes that exist as `app::AppErrorCode` keep exactly today's HTTP statuses
(`statusForAppError`, e.g. `reserved_slug` is 409) and CLI exit codes
(`ExitCodeForAppError`); new codes only add rows. The single table in code is
`url_shortener::commands::all_error_infos()` (Task 01.0 subtask 02).

The envelope (generic endpoint, `cmd`, stdio, TUI) always carries the code
names of the first column. The existing REST **resource routes** keep their
current bodies (Milestone 0003 C3): the legacy `error` strings of the last
column, and their per-field 400 codes (`invalid_redirect_type`,
`invalid_expires_at`, `invalid_enabled`, `invalid_tags`, `invalid_metadata`,
`invalid_campaign`, `invalid_timestamp`, `invalid_bucket`), which surface in
the envelope as `invalid_field` with the field name in `message`.

There is no `job_not_found` code: an unknown job id is `not_found`.

## 2. Transports: how each carries the same command

| Transport | Invocation | Notes |
|---|---|---|
| REST (generic) | `POST /api/v1/commands` with the request envelope as body; `GET /api/v1/commands` = `command.list` | Returns the response envelope; HTTP status from the table above. **Off by default** (see "REST access control" below). |
| REST (resource routes) | e.g. `PATCH /api/v1/links/{slug}` | Static route -> command table (section 5). Body and status unchanged from today; internally `registry.execute`. |
| CLI | `url_shortener cmd <name> --json '<args-object>'` or `--arg key=value` (repeatable) | Prints the response envelope (`--raw` prints only `result`). Exit code from the table. `--json -` reads args from stdin. |
| CLI sugar | `url_shortener link <verb> --flags` (existing) | Flags compile to the same `args` object via the command's `ArgSpec`; output stays as today for backward compatibility (`result` only). |
| TUI | Forms / tables / Command Palette | Each form is generated from the `ArgSpec`; footer shows the equivalent `cmd` line. |
| stdio | `url_shortener serve-stdio [--read-only] [--path-root <dir> \| --no-file-paths]` | NDJSON: one request envelope per input line, one response envelope per output line, in order. Parent-process attach point (e.g. Tauri sidecar). `--path-root` confines `link.import`/`link.export` `path` to one directory; `--no-file-paths` rejects `path` (`unsupported`). |
| IPC (future) | Unix domain socket / Windows named pipe | Same NDJSON framing as stdio; peer-credential identity. |

### REST access control (until Milestone 0002 adds sessions)

The server has no authentication in front of `/api/v1/*` today. Therefore:

- `POST`/`GET /api/v1/commands`, the new `GET /api/v1/links` list route and
  the `/api/v1/jobs*` routes are **disabled unless** the server runs with
  `--command-api-enabled true` (default `false`); while disabled they answer
  exactly like an unmatched route. When enabled, every one of them runs with
  the role from `--command-api-role user|admin` (default `user`, read-only
  commands). The listeners always bind all IPv4 interfaces (`tcp::v4()` in
  `http_server.cpp`), so `--command-api-role admin` is honored **only for
  requests whose TCP peer address is loopback** (`127.0.0.0/8`; `::1` is also
  accepted but cannot occur while the acceptors are IPv4-only); requests from
  any other peer, or with no known peer, run as `user`.
- **Reverse proxies:** the check uses the TCP peer, not `X-Forwarded-For` /
  `Forwarded` (those headers are spoofable and are **not honoured**). Behind a
  reverse proxy on the same host every request arrives from loopback, so
  `--command-api-role admin` would make every client an admin: such
  deployments must keep `--command-api-role user` (decision log D4).
- The generic endpoint requires `Content-Type: application/json` (`415`
  otherwise), which forces a CORS preflight and blocks "simple" cross-site
  `POST`s.
- Commands whose permission is `manage_users` (reserved for Milestone 0002)
  are always refused over REST with `not_authorized` until session-derived
  callers exist, whatever the role flag says.
- The pre-existing resource routes (`/api/v1/links/{slug}...`, `POST /api/v1/links`)
  keep today's open behavior (C3); internally they run as `Admin`.
- Milestone 0002 replaces the role flag with a session-derived `CallerContext`
  (its contract C2, cookie + CSRF).

Worked example, one command on every transport:

```text
REST   curl -X POST $BASE/api/v1/commands -H 'Content-Type: application/json' \
         -d '{"v":1,"command":"link.create","args":{"target_url":"https://example.com/docs","slug":"docs"}}'
CLI    url_shortener cmd link.create --json '{"target_url":"https://example.com/docs","slug":"docs"}'
sugar  url_shortener link create --url https://example.com/docs --slug docs
stdio  echo '{"v":1,"command":"link.create","args":{...}}' | url_shortener serve-stdio
TUI    [2]Links -> n -> fill form -> Create
```

All five produce the same `result` object.

## 3. Commands

Legend: **Perm** = `AccessGuard` permission (`read`, `write`; `migrate` and
`manage_users` exist in the model but no command of this milestone uses them).
**Kind** = `sync` or `job`. **Mut** = mutating (TUI confirms; audit line
written). Types: `string`, `bool`, `int`, `timestamp` (RFC 3339 UTC),
`list<string>`, `map<string,string>`, `object`.

### 3.1 Link commands (existing behavior, now envelope-addressable)

`result` is the existing `LinkView` JSON (`serializeLinkViewJson`) unless noted.

#### `link.create` - Perm `write`, sync, Mut, `dry_run` yes

| Arg | Type | Req | Description |
|---|---|---|---|
| `target_url` | string | yes | URL to shorten (REST body also accepts legacy alias `url`; CLI flag `--url`). |
| `slug` | string | no | Custom slug; generated if omitted. |
| `redirect_type` | enum `temporary`\|`permanent` | no | Default `temporary`. |
| `expires_at` | timestamp | no | Expiry. |
| `enabled` | bool | no | Default `true`. |
| `tags` | list<string> | no | |
| `metadata` | map<string,string> | no | |
| `campaign` | object `{name,source,medium,term,content,id}` \| `null` | no | All fields optional strings; `null` = no campaign (as the REST route accepts today). |

Errors: `invalid_url`, `invalid_slug`, `reserved_slug`, `slug_conflict`, `invalid_field`, `storage_failure`.
The canonical arg is `target_url`; only the REST resource route also accepts
`url` (read first, wins if both are present). The `result` object names the
target `url` (`serializeLinkViewJson`), as today.
Maps to: `POST /api/v1/links`, `link create`.

#### `link.get` - `read`, sync

| Arg | Type | Req | Description |
|---|---|---|---|
| `slug` | string | one of | Look up by slug. |
| `id` | string | one of | Look up by opaque id. Exactly one of `slug`/`id`. |

Errors: `not_found`, `invalid_field`. Maps to: `GET /api/v1/links/{slug}`, `GET /api/v1/links/id/{id}`, `link get`.

#### `link.update` - `write`, sync, Mut, `dry_run` yes

| Arg | Type | Req | Description |
|---|---|---|---|
| `slug` | string | yes | Link to update. |
| `enabled` | bool | no | Absent = untouched. |
| `expires_at` | timestamp \| `null` | no | Absent = untouched; `null` clears. |
| `tags` | list<string> | no | Replaces the full list. |
| `metadata` | map<string,string> | no | Replaces the full map. |
| `campaign` | object \| `null` | no | `null` clears. |

PATCH semantics (absent vs. explicit `null`) are exactly those of
`app::UpdateLinkCommand`. Errors: `not_found`, `invalid_field`, `storage_failure`.
Maps to: `PATCH /api/v1/links/{slug}`, `link update`.

#### `link.delete` - `write`, sync, Mut

Args: `slug` (string, required). Soft delete (sets `deleted_at`). Maps to
`DELETE /api/v1/links/{slug}`, `link delete`.

#### `link.enable`, `link.disable`, `link.restore` - `write`, sync, Mut

Args: `slug` (string, required). One handler family (`SetLinkEnabledCommand` /
`RestoreLinkCommand`). Maps to `POST /api/v1/links/{slug}/enable|disable|restore`,
`link enable|disable|restore`.

#### `link.preview` - `read`, sync

Args: `slug` or `id` (exactly one). Resolved status without redirecting. Maps to
`GET /api/v1/links/{slug}/preview`, `link preview`. (By-`id` is CLI/TUI/generic-REST
only; the resource route stays slug-only.)

`result` is **not** a full `LinkView`: it is the reduced preview projection of
`serializeLinkPreviewJson`, keys in this order:
`{ "slug", "url", "status", "redirect_type", "enabled", "expires_at", "deleted_at" }`.

#### `link.stats` - `read`, sync

| Arg | Type | Req | Description |
|---|---|---|---|
| `slug` | string | yes | |
| `from` | string | no | Range start, decimal **Unix epoch seconds** (as today's `from` query param, parsed by the file-local `parseEpoch` helper in an anonymous namespace of `src/app/legacy_adapters.cpp`, used by `LegacyLinkStatsReader`). |
| `to` | string | no | Range end, epoch seconds. |
| `bucket` | string, one of `hour`\|`day`\|`week` | no | Time-bucket size. Declared as a free string in the `ArgSpec` so the service stays the validator and the REST `invalid_bucket` code is preserved (Task 03.0 subtask 08). |

`result` has two shapes, exactly as `GET /api/v1/links/{slug}/stats` today:

- `from`, `to` and `bucket` all given: the range report (`serializeLinkStatsJson`
  of `LinkStatsView`).
- otherwise: the lifetime counters
  `{ "slug", "total_redirects", "redirects_24h", "redirects_7d", "last_accessed_at": string|null, "created_at" }`
  (`serializeLinkLifetimeStatsJson`, Task 03.0 subtask 08).

A bad timestamp or bucket is `invalid_field` (message names the field; the
resource route keeps its `invalid_timestamp` / `invalid_bucket` strings).
Maps to `GET /api/v1/links/{slug}/stats`, `link stats`.

### 3.2 Browse commands (new; needed by TUI and Milestone 0002/0004)

#### `link.list` - `read`, sync

| Arg | Type | Req | Description |
|---|---|---|---|
| `status` | enum `all`\|`active`\|`disabled`\|`expired`\|`deleted` | no | Default `active` (the TUI sends `all` explicitly). Matches `resolveLinkStatus` (precedence `deleted > disabled > expired > active`); `active` excludes expired links. |
| `q` | string | no | Substring match on slug or target URL. |
| `tag` | string | no | Exact tag. |
| `campaign` | string | no | Campaign name. |
| `sort` | enum `created_at`\|`slug`\|`updated_at` | no | Default `created_at`. |
| `order` | enum `asc`\|`desc` | no | Default `desc`. |
| `offset` | int >= 0 | no | Default 0. |
| `limit` | int 1..500 | no | Default 50. |

`result`: `{ "items": [LinkView...], "offset": n, "limit": n, "total": n }`.
Backed by `app::ILinkLister` over the new `IMetadataRepository::ListLinksPage`
(Task 03.0 subtasks 01 and 12; lifecycle, tag and campaign filters are applied
in the app layer because the SQL backends keep them in `attributes`). Maps to:
new `GET /api/v1/links` (query params = args; gated, see "REST access
control"), `link list`. _Note:_ default `status` is recorded in the decision
log (Q9).

#### `db.tables` - `read`, sync

No args. `result`: `{ "tables": [ { "name": "links", "rows": 1204, "writable": true, "columns": [ {"name":"slug","type":"string","sortable":true,"searchable":true} ] }, ... ] }`.
`sortable` = allowed as `db.rows` `sort`; `searchable` = participates in `db.rows` `q` (both additive, Task 03.0 subtask 15).
Logical, port-backed tables only: `links`, `click_events`, `jobs`. Never
returns auth/session tables or columns holding hashes, tokens, salts or DSNs.

#### `db.rows` - `read`, sync

| Arg | Type | Req | Description |
|---|---|---|---|
| `table` | string | yes | One of `db.tables` names; else `not_found`. |
| `q` | string | no | Free-text filter (per-table meaning, documented in `db.tables` columns). |
| `sort` / `order` | string / enum | no | Allowed columns only. |
| `offset` / `limit` | int | no | Same bounds as `link.list`. |

`result`: `{ "table": "...", "columns": [...], "rows": [ {...} ], "offset": n, "limit": n, "total": n }`.
`click_events` rows expose only `client_id_hash` (never raw identifiers), as
stored. The `click_events` table reads the process-local analytics repository,
so it is empty in a CLI/TUI process that did not serve redirects (Task 03.0
subtask 16). The `jobs` table lists the jobs of the current process (Task 05.0
subtask 21).

### 3.3 Pair commands: insert, import, export

#### `link.import` - `write`, **job**, Mut, `dry_run` yes

Bulk-insert `full_URL -> short_URL` pairs.

| Arg | Type | Req | Description |
|---|---|---|---|
| `format` | enum `csv`\|`ndjson` | yes | `csv`: `full_url,slug` per line (slug may be blank); `ndjson`: one `link.create` args object per line. |
| `data` | string | one of | Inline payload (<= `--max-request-body-bytes`). |
| `path` | string | one of | Local file path (CLI/TUI/stdio only; rejected on REST with `unsupported`; confined by `serve-stdio --path-root`, rejected under `--no-file-paths`). |
| `on_conflict` | enum `skip`\|`fail`\|`overwrite` | no | Default `skip`. `overwrite` replaces the target of an existing, non-deleted link (`LinkCommandService::ReplaceLinkTarget`, open decision); not offered by REST. |

Each row goes through `LinkCommandService::CreateLink` (same validation, SSRF
check and slug rules as `link.create`; no second code path). The CSV header
and columns are exactly `full_url,slug`. Job `result`:
`{ "total": n, "created": n, "skipped": n, "failed": n, "errors": [ {"line": n, "code": "invalid_url"} ], "errors_omitted": n, "dry_run": false }`
(`errors` capped at 100; `errors_omitted` counts the errors beyond the cap; `dry_run` echoes `options.dry_run`; Task 05.0 subtask 08).

#### `link.export` - `read` (`write` with `path`), **job**

Args: `format` (`csv`|`ndjson`, required), `status`, `q`, `tag`, `campaign` (as `link.list`), `path` (optional local file, create-new only; otherwise inline `data` in the job result, size-capped). Job `result`: `{ "rows": n, "path": "..." | null, "data": "..." | null }`.
CSV columns are `full_url,slug` (re-importable). Cells are not formula-escaped:
targets are always `http(s)://...` and slugs match `^[A-Za-z0-9][A-Za-z0-9_-]{2,63}$`,
so no cell can start with `=`, `+`, `-` or `@`. `path` writes a file, so the
descriptor's argument-dependent permission hook (`permission_for`, ADR 0002
section 2, decision log D16) raises the required permission to `write` when
`path` is present: a read-only session (`ControlSet::User`) gets
`not_authorized` before any job is created; inline export stays `read`.
`command.list` reports the base permission `read`.

### 3.4 Job commands

| Command | Perm | Args | Result |
|---|---|---|---|
| `job.get` | `read` | `id` | `{ id, command, state, progress{done,total}, result?, error?, created_at, started_at?, finished_at? }` (`started_at` set when the job leaves `queued`) |
| `job.list` | `read` | `state?`, `limit?`, `offset?` | `{ items:[job...], total }` |
| `job.cancel` | `write` | `id` | job object; cancelling a finished job is a no-op returning its final state |

States: `queued`, `running`, `succeeded`, `failed`, `cancelled`. Unknown id: `not_found`.
Jobs carry no owner in V1 (single local operator, or one REST role); when
Milestone 0002 adds users, `job.*` must filter by principal.

### 3.5 System and introspection

| Command | Perm | Result |
|---|---|---|
| `command.list` | `read` | `{ "commands": [ { name, summary, perm, kind, mutating, dry_run, args:[{name,type,required,enum?,doc}] } ] }` - the descriptors themselves. Drives TUI palette/forms, CLI `--help`, client codegen. |
| `system.info` | `read` | `{ version, backend:{metadata,cache,analytics,rate_limit}, persistent:bool, read_only:bool, shortener:{base_domain,generated_slug_length,default_redirect_type,default_expiry_seconds,allow_private_targets,analytics_enabled,max_request_body_bytes,max_request_target_length,request_id_max_length} }` - only allowlisted backend *names* and the non-secret `shortener_*`/hardening fields of `ServerConfig` are emitted (never TLS paths/passphrase, never `analytics_client_hash_salt`, never DSNs/addresses/paths); any future free-form value goes through `::observability::redactSecretValue` (`storage_observability.hpp`). Backs the TUI Settings screen (ADR 0003 D13). |

### 3.6 Deliberately not commands

Same exclusions as ADR 0001: redirects (`GET /{slug}`, `/r/{slug}`),
observability (`/healthz`, `/readyz`, `/metrics`), compatibility aliases
(`/api/v1/short-urls`), generic URI-store fallback, and the `qr`/`routing`
placeholders (`501`). Authentication and user-management commands
(`manage_users`) are **reserved** for Milestone 0002 Task 07.0, which will add
`auth.*` / `user.*` descriptors to this registry; they are not designed here.

## 4. Job model

```text
queued --> running --> succeeded
                  \--> failed
queued|running --cancel--> cancelled
```

- Created by any `kind = job` command (or `options.async` on `async_capable`).
- Held in memory by one process-wide `JobRunner` of the process that owns the
  registry (REST server, TUI, `serve-stdio`, `cmd`), wired once by
  `composition::build_command_runtime` (Task 05.0 subtask 20). A one-shot `cmd` CLI invocation that starts a job waits for
  it to finish and prints the final `job.get` envelope (`--no-wait` prints the
  accepted envelope, which is only useful against a long-lived process). The
  waiting arrives with Task 05.0 subtask 20 (a follow-up edit to the `cmd`
  dispatch of Task 04.0 subtask 13); before that, `cmd` prints the accepted
  envelope.
- Bounded worker pool and queue; a full queue yields `busy`.
- Cancellation is cooperative (checked between rows/pages); partial effects of
  `link.import` before cancel are kept and reported in the job result.

| `PATCH /api/v1/links/{slug}` | `link.update` |

New routes are registered in `RouteRegistry` (so `docs/api/README.md` and the

`/api/v1/jobs*`) are gated by `--command-api-enabled` and run with
`--command-api-role` (section 2, "REST access control").

## 6. Adding a command / adding a transport

**New command:** add a `CommandDescriptor` (name, summary, `ArgSpec`s, perm,
kind, mut) and one handler (decode args -> DTO -> service -> encode). It is
then automatically in `command.list`, `POST /api/v1/commands`, `cmd`,
`serve-stdio`, the TUI palette/form, `--help` and this catalog. Add a row to
section 5 only if a nicer REST route is wanted.

**New transport (e.g. IPC):** implement `ITransportAdapter` (frame in -> call
`CommandRegistry::execute` -> frame out), register it in `src/composition/`.
No command code changes. Add the transport to the conformance suite's adapter
list; it must pass the shared corpus.

## 7. Conformance

A single corpus of `(request envelope, expected response envelope)` pairs
under `tests/conformance/commands/` is replayed through every adapter (direct
registry, REST generic, REST resource routes where mapped, CLI `cmd`,
`serve-stdio`, TUI in-process client). Identical `result`/`error.code` across
adapters is the executable definition of "identical commands".
