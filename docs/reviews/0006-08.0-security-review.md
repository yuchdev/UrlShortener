## Assets & trust boundaries

- **Untrusted input:** `cmd` argv (command name, `--arg NAME=VALUE`, `--json`, `--id`,
  flag values) and NDJSON/stdin payloads. Threat models T-77 (never echo operand
  values), T-78 (escape before any envelope), T-79 (bounded stdin).
- **Sinks crossed by the change:** stdout envelope (`serialize_response`), stderr
  diagnostics (`print_response`, `main.cpp` boundary), process exit code, and the
  FATAL structured log (which the change deliberately keeps `cmd` away from).
- **Docs assets:** security claims that operators rely on (SSRF rules, the `0.0.0.0`
  bind + loopback-admin command API, read-only/path policy, redaction, auth-broker
  local-only, TUI security section) plus any secret material in examples.

## Findings

### [LOW] Unknown-`cmd`-option diagnostic echoes the attacker-controlled flag stem to stderr (CWE-117)

- Vector / evidence: `src/cli_parser.cpp:639-640` throws
  `"Unknown cmd option: " + token.substr(0, token.find('='))`; the new boundary at
  `src/main.cpp:88-90` prints `e.what()` to stderr for any `cmd` usage error. The
  flag stem is a raw argv token (truncated only at `=`) and may contain newlines.
  Reproduced: `url_shortener cmd link.get $'--evil\nFATAL injected'` emits
  `cmd failed: invalid_request: Unknown cmd option: --evil` followed by a forged
  `FATAL injected` line on stderr.
- Impact: output/log injection into whatever captures the child process stderr
  (a parent webview/TUI/sidecar driving `cmd`, or a log collector). An attacker who
  controls an operand token can forge log lines (e.g. a fake `FATAL`). No secret
  value leaks: the stem is truncated at `=`, so T-77's value-non-echo holds, and
  this is stderr only, not the structured audit log. The vector is essentially
  pre-existing (before the change the same stem reached the FATAL logger via the
  top-level handler); the change moved it to plain stderr. Not a regression, and
  **not** on either path the task flags as must-be-clean.
- Mitigation (follow-up): strip control characters / collapse newlines from the
  diagnostic, or drop the stem entirely and emit a fixed `Unknown cmd option.`
  message (the stem is not needed). Hand to `cpp-expert`; regression test to
  `testing-expert` (assert no newline passes through the boundary).

### [LOW] `docs/tui/README.md` understates where secret redaction lives

- Vector / evidence: `docs/tui/README.md:366` states secret-column hiding/row-JSON
  redaction "is enforced in the `db.*` command handlers, not in the TUI." The TUI
  also implements it as defense-in-depth: `src/tui/tables_model.cpp:136-152,296-297`
  (`is_secret_column_name`, `redact_secret_fields`, column skip).
- Impact: documentation imprecision only. It *understates* a protection (claims the
  TUI has none), so it does not overstate isolation and is not merge-blocking.
- Mitigation: reword to "enforced in the `db.*` handlers and, defense-in-depth, in
  the TUI tables model." Hand to `docs-updater`.

## Claims verified against code (no overstatement found)

- **Invalid command name / malformed `--arg` (the task's must-be-clean paths):**
  `src/cli/cmd_dispatch.cpp:362-403` maps both to a fixed `invalid_envelope`
  envelope ("invalid field command" / "malformed --arg operand"), exit 2, on
  stdout; `--raw` prints only a value-free `cmd failed: invalid_envelope:` line.
  The rejected name/operand is never echoed. `CmdCliCommand::malformed_arg` is a
  value-free marker; the operand is dropped, never stored. Confirmed at runtime:
  clean envelope, exit 2, empty stderr, no `FATAL`. The echoed `id` is
  `jsonString`-escaped in `serialize_response` (`src/commands/envelope.cpp:399`),
  satisfying T-78.
- **`main.cpp` boundary scope:** `src/main.cpp:85-92` catches only when
  `argv[1] == "cmd"`; every other mode rethrows to the FATAL handler. No
  security-relevant failure in `serve`/`serve-stdio`/`link` is masked. All other
  `cmd` usage-error messages reaching `e.what()` are fixed, value-free strings
  (verified each throw site in `parseCmdCommand`, `cmdFlagValue`,
  `extract_storage_config_flag`, `parseBool`) except the stem noted above. Exit
  code 2 is consistent with the catalog's bad-input code.
- **`0.0.0.0` bind + `--command-api-role`:** `src/http/command_bridge.cpp:320-372`
  grants Admin only when `command_api_role == "admin"` AND the TCP peer is loopback
  (`127.0.0.0/8`, `::1`, v4-mapped loopback); fail-closed on an absent peer; XFF is
  not consulted. Docs match and warn correctly about the reverse-proxy pitfall
  (`docs/commands/README.md:141-165`, `ARCHITECTURE.md:118-119`,
  `decision-log.md` D4, README `--command-api-role admin` note). Not overstated.
- **Redaction:** `CLAUDE.md:146` now accurately describes
  `observability::redactSecretValue` (`src/observability/storage_observability.cpp:38-43`:
  keys containing password/secret/token → `[REDACTED]`; DSN password segment only).
  The prior "key" claim was dropped. The security testplan's "keys and salts"
  coverage is backed by the separate table-browse markers
  (`src/tui/tables_model.cpp:143`: hash/token/salt/secret/password/dsn) and the
  not-logged allowlist for the salt; no overstatement.
- **Read-only / path policy:** `docs/cli/README.md:196-253` matches
  `src/cli_parser.cpp:868-907,1006-1017` (`--no-file-paths`/`--path-root` mutual
  exclusion, read-only cannot use `path`). `serve-stdio`/`tui`/`cmd` default-local-admin
  risk is documented accurately as requiring `--read-only` + `--no-file-paths` for
  untrusted input.
- **Auth broker local-only** is correctly kept distinct from the command API in all
  changed docs (`CLAUDE.md:122`, `docs/tui/README.md`, `adding-a-transport.md:574`).
